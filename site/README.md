# upnext.games

UpNext's website: one page in plain HTML and CSS, with no build step, no outside scripts or fonts, and no trackers. `main.js` only types the example requests and adds copy buttons; the page reads the same without it. The colours and fonts are the app's own (the Arcade theme in `web/src/index.css`), and the fonts are copied from the web UI's packages with their licences in `fonts/`. `images/pick.webp` is `docs/images/pick.png` converted to WebP, the other screenshots are of a made-up library from `upnext mock-library`, and `images/share.png` is the picture a link preview shows. The icon (a d-pad with Up pressed) is drawn inline in `index.html` and `404.html` and is also `favicon.svg`; `apple-touch-icon.png` is the same drawing at 180 pixels, square.

To look at it, serve the folder (`python3 -m http.server -d site 8080`) and open http://127.0.0.1:8080.

## Deploying

The site is a Cloudflare Pages project on the bare `upnext.games` (and `www.upnext.games`, if wanted). It never goes on `verdicts.upnext.games`: that name is the backlog verdicts Worker, whose root and `/terms` pages installed copies of UpNext rely on, and the two stay separate deployments. Create the project from this repository in the Cloudflare dashboard (Workers & Pages, Create, Pages, Connect to Git) with no framework preset, an empty build command and `site` as the build output directory, and `site/*` as the only include path under Build watch paths, so a push to `main` publishes the site only when it changes `site/`; or upload the folder by hand with `npx wrangler pages deploy site --project-name upnext-site`. Then add `upnext.games` under the project's Custom domains, which makes the DNS record itself since the domain is on the same account. Leave Cloudflare Web Analytics off for the project. The repository's CI skips `site/`, since there is nothing in it to build or test. `_headers` sets the security headers, including a content security policy that allows only the site's own files, and `404.html` is the page for addresses that don't exist.

The Windows, Debian/Fedora and Arch Download buttons go to `releases/latest`, which always opens the newest full release (GitHub skips prereleases there); the footer's Releases link lists them all. The Android card has no Download button until a release carries the APK, which needs the app's signing key (`docs/install/android.md`); add one pointing at `releases/latest` then, and change its status line. The same goes for the Flatpak bundle.
